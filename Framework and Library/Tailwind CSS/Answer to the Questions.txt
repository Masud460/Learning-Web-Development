32. Tailwind CSS is an utility-first framework that generates thousands of CSS classes. However, using it directly in development would result in a massive, unoptimized CSS file (often several MBs).

  Key Reasons for Building Tailwind:

  1.Purge Unused CSS (Tree Shaking)

  In production, you don’t need all utility classes—only the ones you actually use.

  The build process removes unused classes, drastically reducing file size (e.g., from 3MB+ → 10KB).

  2.Minification & Optimization

  The generated CSS is compressed (removes whitespace, comments, etc.).

  Improves load time and performance.

  3.Applying PostCSS Plugins

  Tailwind uses PostCSS under the hood.

  Plugins like autoprefixer add vendor prefixes (-webkit-, -moz-).

  4.Handling Custom Configurations

  Your tailwind.config.js (colors, fonts, breakpoints) is processed during build.

33. This is so simple, just write the code in your package.json's scripts object:

35. Just add '.min' in package.json file after the output file name and before the file extension name and add '--minify' after the output file name(e.g. "build": "tailwindcss -i input.css -o ./css/styles.min.css --minify")
