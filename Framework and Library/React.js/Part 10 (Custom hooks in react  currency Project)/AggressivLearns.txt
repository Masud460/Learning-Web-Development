When we build reusable components in React, we often need a way to notify the parent component whenever an input value changes. Instead of directly managing state inside the reusable component, we pass down a callback function as a prop.

In the parent component, we provide the callback like this:

<InputBox onAmountChange={(amount) => setAmount(amount)} />


Here, onAmountChange is a function that updates the parent’s state (setAmount).

Inside the InputBox component, we accept this prop and call it whenever the input value changes:

function InputBox({ onAmountChange }) {
  return (
    <input
      onChange={(e) => onAmountChange?.(Number(e.target.value))}
    />
  );
}


This way:

The parent component controls the state.

The child component remains reusable and doesn’t need to know what happens with the value.

The input’s value is passed “up” through the callback, and the parent decides how to use it.

✅ This pattern is called “lifting state up”, and it’s one of the most common React practices for managing state between components.

1. Props and Callback Functions (Child ↔ Parent Communication)
<InputBox onAmountChange={(amount) => setAmount(amount)} />


Parent passes a function (setAmount) to the child via props (onAmountChange).

👉 Learning: This is how data flows up from child → parent. (Called “lifting state up.”)

7. Custom Hook (useCurrencyInfo)
function useCurrencyInfo(currency) {
  const [data, setData] = useState({});
  useEffect(() => {
    fetch(`.../${currency}.json`)
      .then(res => res.json())
      .then(res => setData(res[currency]))
  }, [currency]);
  return data;
}


You made your own hook for fetching currency data.

Whenever currency changes, useEffect runs again → fetches new data.
👉 Learning: Put reusable logic in custom hooks for cleaner code.
